# Labels and sprites — text, billboard, point

The `text` / `billboard` / `point` materials of a `vector` layer follow MapLibre's symbol model. Sizes, `geometryTypes` and draping: [vector-styling.md](vector-styling.md). Returning values per feature: [feature-evaluator.md](feature-evaluator.md). Extruded 3D text as a mesh (`text3D`, a font file URL instead of a font family): [declarative-api.md](declarative-api.md#mesh--effect--light-descriptors-the-other-half-of-the-declarative-api).

## Text from feature properties, fonts

- `text` labels sourced from feature properties are set via the evaluator, and the evaluate callback must return **both** `text` and `show: true` — returning only `text` leaves every label hidden (`return { text, show: !!text }`). Register a Google Font first (`fetchFontFamilyFromCss` is exported from `@navaramap/three`): `view.addFontFamily(await fetchFontFamilyFromCss("Arsenal", "https://fonts.googleapis.com/css2?family=Arsenal:wght@700"))`, then reference it as `text: { font: "Arsenal", ... }`.

## Billboard images

- **`billboard.url` is the layer's default image; per-feature icons come from the evaluator's `image`.** Return `image: "/icons/x.svg"` from `evaluate()` for each feature: every distinct URL loads once and is packed into the layer's atlas. `image: null` clears a per-feature image and falls back to `url`; with no `url` on the material that feature is invisible, so omit `url` only when every feature gets an `image`.

## Orientation

- **Labels and sprites orient like MapLibre symbols, and each feature can differ.** Three options on `text` / `billboard` / `point`. The facing option (`textFacing` / `billboardFacing` / `pointFacing`) is MapLibre's `*-pitch-alignment`: `"upright"` keeps the quad in the screen plane (never foreshortened), `"flat"` lays it on the globe surface around the anchor, wrapped to the curvature (so a pixel-sized label at globe scale stays on the surface instead of lifting off at its ends), so it reads as painted on the surface. `rotateWithCamera` is `*-rotation-alignment`: `true` keeps it reading left to right (a screen-aligned billboard, or for `"flat"` a yaw), `false` aligns it with the map (upright: on screen but turned with the camera heading so its x-axis points east, upside down when looking south; flat: north-up). **Both default to MapLibre's `auto`:** `rotateWithCamera` resolves to `true` for `placement: "point"` and `false` along a line, and an unset facing to `"flat"` exactly when `rotateWithCamera` is `false` — so setting only `rotateWithCamera: false` on a point label makes it flat north-up, not upright. `rotation` (degrees, clockwise from the front, default `0`) then spins it inside that plane about its **anchor** — `anchor` picks where inside the quad the pivot sits. **All three are also per-feature** from a feature evaluator, returned as `facing` / `rotateWithCamera` / `rotation`, so one batch can hold labels at eight different bearings in a single draw call. **Evaluated values win over the material** — `layer.update()` re-emits `featureUpdated`, so a registered evaluator re-runs and reapplies its values after any material change. To let the material govern a feature again, have the evaluator return the material value for it (an evaluator that simply stops returning a property leaves the last value in place). Gotchas: only a flat quad has a back, so `backfaceCulling: true` (default `false`) only matters for flat labels — it trims a large one at the limb, where its wrapped-over parts face away; for `"flat"` keep `offsetDepth: true` (the default) or the label z-fights the surface it lies on; and a point label's declutter box turns with it (`rotation`, facing, and the camera heading of a map-aligned quad, as the shader lays it out), so a turned label claims the space it is drawn over.

## Anchor, offset, translate

- **Place labels and sprites with `anchor` + `offset`, like MapLibre's `text-anchor`/`icon-anchor` and `*-offset`.** `anchor` names the part of the text block or quad that sits on the position (`"center"` default, `"top"`, `"bottom-left"`, …); `offset` is `{x, y}` with **+y down**. Units differ: text `offset` is in **ems** (× `size`), billboard/point `offset` is in the unit of `size` (px, or metres with `sizeInMeters`). Both lie in the quad's plane, so they turn with `rotation`. Billboard `size` is the quad's height, not a scale of the image; `sizeRelativeToImage: true` makes it one (MapLibre's `icon-size`: `size: 1` draws the image at its natural pixel size, while `offset` stays in px/m). A pin icon wants `anchor: "bottom"`; a label beside it uses its own anchor/offset — text is **not** auto-placed next to the icon. `textAlign: "auto"` justifies multi-line text towards the anchor's side. All of `anchor`/`offset`/`textAlign` are also per-feature evaluator values. `translate` (`{x, y}` screen px, +y down, layer-level only) shifts the drawn quad after projection — it does **not** turn with `rotation`; `translateAnchor: "map"` (default) turns it with the camera heading (+x east), `"viewport"` keeps screen axes. `variableAnchors: [{anchor, offset?}, …]` (text only, offsets in ems, per-feature too) lets declutter move a blocked point label to the first free placement — it **needs `declutter`** (without it the first entry is used), replaces `anchor`/`offset` when non-empty, and is ignored along lines.

## Text outline and line height

- **Text `outlineWidth`/`outlineBlur` are in 1/64 em, not pixels, and `lineHeight` is in ems.** A halo of `h` px on `size`-px text is `outlineWidth: h / size * 64`, so it keeps its proportion at any size. The outline plus its fade reach at most 17.5/64 em past the glyph (8/64 with `highQuality`) less half a screen pixel, so near that limit small text gets proportionally thinner outlines, and a wider fade is narrowed. `outlineColor`/`outlineOpacity`/`outlineWidth`/`outlineBlur` are also per-feature evaluator values. Unset `lineHeight` spaces lines by the font's own line height, which varies per font; set it (MapLibre's default is `1.2`) for font-independent spacing.

## Along-line placement

- **Along-line placement** (`text` / `billboard` / `point` with `geometryTypes: ["line"]` + `placement: "line" | "line-center"`): `spacing` is **screen pixels** for `vector-tile` and `geojson` alike, resolved per anchor as the camera moves (anchors thin out / fill in without moving; the on-screen gap stays within 1–2× `spacing`, even across a pitched view). MapLibre's `symbol-spacing` rules apply on top: a symbol longer than ¾ `spacing` spreads repeats to its length + ¼ `spacing` (not dropped), a same-text label within `spacing / 2` of an earlier one in the tile is dropped, and vector tiles place anchors only inside their own bounds — so on vector tiles repeats are at most ~one tile (512–1024 px) apart however large `spacing` is. Very close in (GeoJSON street level, or vector tiles overscaled far past their zoom) anchors stop filling in and sit further apart than asked. `placement`, `spacing` and `rotateToLine` are baked when features are built: `layer.update()` cannot change them, delete and re-add the layer. Along a line, facing and `rotateWithCamera` default to flat + `false` (MapLibre's `auto`), so text lies on the road and follows it word by word (letters within a word stay straight); `spreadGlyphs: true` places each glyph on its own (MapLibre's default street name) and is live-updatable, and the evaluator can override it per feature (`spreadGlyphs`), e.g. to keep cursive scripts or fonts word by word. The four layouts: flat + `rotateWithCamera: false` lies on the ground along the line; `"upright"` + `false` stays on screen at constant size, turned to the line as it runs on screen (MapLibre `map` rotation, `viewport` pitch); `rotateWithCamera: true` + `spreadGlyphs` turns each glyph to the camera (`viewport-glyph`); `rotateWithCamera: true` without `spreadGlyphs` draws the label **straight** at each anchor like a point label (`viewport`: no bend, no flip, no `maxAngle` test, background drawn, `lineOffset` ignored). `rotation` spins each glyph of a bent label about its own centre (MapLibre `text-rotate`), or a straight label as a whole. Sprites follow the line by default (flat, map-aligned; the tangent bearing is added to `rotation` with `rotateToLine`). References: `example/pages/styling/line-placement` (GeoJSON), `styling/mvt-line-labels` (MVT).

## Decluttering

- **Label decluttering:** `text`/`point`/`billboard` materials declutter by default (`declutter: true`) — screen-overlapping labels hide the lower-priority one (with a fade). Set `declutter: false` on the material to draw every label unconditionally. Finer control, as MapLibre's `*-overlap` / `*-ignore-placement`: `overlap: "always"` keeps the label shown but its box still hides later `"never"` labels, `"cooperative"` hides it only behind `"never"` labels, and `ignorePlacement: true` lets later labels overlap it (`"always"` + `ignorePlacement` equals `declutter: false`). `declutterPadding` (screen px, 1–4 CSS-ordered values, default `[2]`) grows the collision box, also for `sizeInMeters` labels. A layer's `text` and `billboard` at the same feature and anchor are placed as a pair (never blocking each other) unless both are `standalone`; `standalone: false` on both makes them show together or not at all. Default `true` on both: independent, so a label overlapping its own icon competes with it like any other symbol. Placement priority: layer-level `declutterPriority` on the material, overridable per feature by returning `declutterPriority` from `evaluate()` — higher wins; `declutterRank` on the material is compared before any priority, so a per-feature priority never beats a higher-ranked layer (the MapLibre plugin sets it to the style layer index); among equal priorities currently-shown labels are sticky (hysteresis), then ties resolve deterministically by anchor position. The placement math itself is a Rust kernel (`declutterPlace` in `navara_wasm_api`); the TS `DeclutterManager` only orchestrates. Reference: `example/pages/styling/mvt-text`.
