# Vector styling — points, polylines, polygons

Material blocks of a `vector` layer over `geojson` / `vector-tile` sources. The basic pattern and the source ↔ layer ↔ material table: [declarative-api.md](declarative-api.md). Orientation, anchors, outlines, along-line placement and decluttering of `text` / `billboard` / `point`: [labels-and-sprites.md](labels-and-sprites.md). Per-feature values: [feature-evaluator.md](feature-evaluator.md).

## Which geometry a material draws

- **Vector materials consume only their native geometry unless `geometryTypes` opts in more.** `point`/`billboard`/`text` default to `["point"]`, `polyline` to `["line"]` — polygon data with only a `polyline` material renders nothing. Opt in with e.g. `polyline: { geometryTypes: ["line", "polygon"] }` (polygon boundary rings incl. holes render as closed polylines) or `point: { geometryTypes: ["point", "line", "polygon"] }` (one point per vertex, ring-closing duplicate skipped). On lines and polygons `text`/`billboard` differ from `point`, as MapLibre symbols differ from circles: one anchor per line string at its first vertex (dropped on a vector tile when that vertex is in the tile buffer) and one per polygon (MultiPolygon part) at its pole of inaccessibility, not per vertex; `placement: "line" | "line-center"` walks the rings instead (clip edges skipped on vector tiles) for all three. Per-vertex `point` markers on dense vector-tile polygons cost one instance per vertex (hundreds of thousands per view), so keep them to sparse data. The array **replaces** the default, so include the native category to keep it. Boundary polylines are at ring base height only — extruded-polygon edges remain `polygon.outline`'s job. Two caveats: (1) `geometryTypes` is construction-time config — `layer.update()` applies a new value only to tiles loaded afterwards (resident tiles keep their old geometry, and toggling back never removes already-built derivations); set it at layer creation or delete/re-add the layer. (2) On tiled paths derivation walks tile-clipped rings; boundary polylines drop clip-introduced edges automatically (draped and non-draped are both clean), but vector-tile-derived points can still appear at clip-introduced vertices near tile edges.

## Several layers over one source

- **One source can back several layers.** Point many `addLayer({ type: "vector", source })` calls at the same vector-tile source to style sublayers separately (`sourceLayers: ["water"]`, `["roads"]`, …) or to stack materials on the same sublayer (a `polygon` fill layer plus a `polyline` outline layer over `sourceLayers: ["buildings"]`). Each tile is fetched and decoded once no matter how many layers match; every matching layer gets its own features, batch-id space and `layer.update()`/`delete()` handle. Layers with no `sourceLayers` match every MVT sublayer. Stacking a wider symbol under a narrower one (an outline) is the common use: add the wider layer first, since render order is add order. Two stacked **point** layers need `declutter: false` on both — screen-space decluttering is on by default, so the sprites at identical positions suppress each other and the underlay silently vanishes. Non-clamped stacked polylines also need a small `height` difference or they z-fight.

## Points, billboards and draping

- `point` / `billboard` / `text` `size` is in **meters** by default (`sizeInMeters ?? true`) — a 24 m dot is invisible from a high camera. For constant on-screen size markers and labels set `sizeInMeters: false` (size becomes pixels).
- `clampToGround` vectors are **baked into globe surface tiles**, so they only render where some tile-producing layer exists (raster or terrain). With no basemap at all, add a plain ellipsoid surface to drape onto: `view.addLayer({ type: "terrain", ellipsoid: {} })`, and color the bare globe via `view.globe.color = new Color().setStyle(...)`.
- **Polygon outlines are `outlineShow` + `outlineColor` + `outlineWidth` (pixels), GeoJSON sources only for now.** `outline` only decides whether outline geometry is built, at initial load (unset = inferred from `outlineShow`), so a layer that turns `outlineShow` on later via `layer.update()` must start with `outline: true`. `surfaceShow: false` (effective while `outlineShow` is `true`) draws the outline without the fill. Outlines are not rendered when `clampToGround: true` (they only exist on the non-draped 3D path); for vector tiles or draped data, stack a `polyline` layer with `geometryTypes: ["polygon"]` instead (see above).

## Polylines

- **Non-draped vector polylines are lit; draped ones are unlit.** `clampToGround: false` polylines render through a lit shader (`material.lights = !isTexturized`), so with zero lights they draw **black** — invisible on a dark basemap and a classic "the line is missing" trap. Draped (`clampToGround: true`) lines bake into tile textures and ignore lights. Fix: add `view.addLight({ ambient: { intensity: 1 } })` (needs DefaultPlugin) to show the line at its plain color.
- **Polyline `width` is screen px, but clamped by `maxWidth` in world meters (default 1000).** From a whole-globe camera 1 px ≈ 11 km, so the default clamp makes any line sub-pixel — pass `maxWidth` (e.g. `100_000`) for high-altitude views. Draped polylines additionally vanish entirely at globe-scale zoom (bake resolution) regardless of `maxWidth` (verified at camera height ≈ 9,000 km; they render fine at ≈ 2,000 km) — use non-draped lines for global arcs.
- **Dashed and dotted polylines are `dashArray` + `cap`, in MapLibre `line-dasharray` units.** `polyline: { dashArray: [3, 2] }` alternates dash and gap lengths in multiples of the line width, on layer materials and on `PolylineMeshDesc` alike; the period is the sum of the entries, so an odd-length array's last dash joins its first (`[1, 2, 1]` = two-width dashes). A dotted line is a zero-length dash with a round cap: `dashArray: [0, 2], cap: "round"` — with the default `"butt"` that array draws nothing. `[]` is solid. `cap` also shapes the ends of the line itself, solid or not (`"round"` / `"square"` reach half a line width past each end; closed rings have no ends), while `"square"` leaves the dashes' own ends square. Per feature, return `dashArray` (and `cap`) from the evaluator, for every feature once for any (`[]` for the solid ones): the first per-feature write makes unstyled features solid, not the material's pattern. Gaps still pick as the line. Every line's dashes stretch up to 2× with camera distance. Draped (`clampToGround`) layer lines start the pattern with a dash and, for a GeoJSON source, continue it across tiles; vector-tile (MVT) sources and non-clamped `tiled` lines restart it at each tile boundary. Non-clamped lines (layers and all `PolylineMeshDesc`) keep one continuous pattern starting in the middle of its longest gap rather than with a dash. A view holds at most 255 patterns in use at once, of at most 16 dashes each; further ones draw solid with a console warning, and a pattern no line uses any more frees its slot.
